# 🇹🇭 แผนลงมือเฟส 1 — ฉบับภาษาไทย

> **สถานะ 2026-09-29:** งาน 1 ✅ · งาน 2 ✅ · schema + Action `db-migrate` + `scripts/import_csv.py` ✅ (ดึงมาทำก่อนจากงาน 7–8) · ต่อไป: งาน 3–6

← [[Project - Stock Count]] · 🇬🇧 ฉบับเต็ม (มีโค้ด): [[2026-09-28-stock-count-phase1]] · spec: [[2026-09-28-stock-count-design]]

> ฉบับนี้อธิบาย **ทำอะไร ทำไม และดูยังไงว่าเสร็จ** ของแต่ละงาน ส่วนโค้ดและคำสั่งเต็มอยู่ในฉบับอังกฤษ (ไม่ได้คัดโค้ดมาไว้สองที่ เพราะแก้ที่หนึ่งแล้วอีกที่จะเพี้ยน)

## ภาพรวม
- **เป้าหมาย:** พนักงานสแกน QR ที่ชั้น → พิมพ์ยอดในแชท LINE → ยอด (+รูปชั้น) เข้า Supabase รายวัน → bot สรุปรายการที่ไม่ตรงกับระบบ
- **โครงสร้าง:** FastAPI รับ webhook จาก LINE → ส่งต่อให้ `StockService` (กติกาทั้งหมด) → คุยกับฐานข้อมูลผ่าน `Repo` · ตอนเทสต์ใช้ `InMemoryRepo` ตอนใช้จริงใช้ `SupabaseRepo`
- **เครื่องมือ:** Python 3.12 · FastAPI · line-bot-sdk v3 · supabase-py · PyYAML · qrcode + Pillow · pytest · Supabase CLI ผ่าน `npx` · ngrok
- **วิธีทำทุกงาน:** เขียนเทสต์ก่อน → รันให้เห็นว่าพัง → เขียนโค้ด → รันให้ผ่าน → commit

## กติกาที่ใช้กับทุกงาน
- config ที่คนแก้ = `config.yaml` · ความลับ = `.env` (ห้าม commit)
- โค้ด/ชื่อตัวแปร/comment เป็นภาษาอังกฤษ · ข้อความที่ bot ตอบเป็นภาษาไทย และอยู่ใน `messages.py` ที่เดียว
- เก็บแค่ LINE user ID ของพนักงาน ไม่เก็บชื่อ/เบอร์
- รอบนับ 1 รอบต่อ 1 วัน **ตามเวลาไทย** (Asia/Bangkok)
- เปิดชั้นแล้วมีเวลา 10 นาที · บันทึกยอดแล้วนับ 10 นาทีใหม่ (ให้มีเวลาส่งรูป)
- แสดงยอดในระบบให้พนักงานเห็น (ไม่ใช้ blind count)
- ยอดที่ควรมี = `back_qty` ล่าสุดของสินค้านั้น (POC นับแค่หลังร้าน)
- บันทึกทีละชั้นแบบ "ทั้งชั้นหรือไม่เลย" · นับซ้ำ = ทับของเดิม
- Supabase free plan → GitHub Action รัน `supabase db push` เมื่อ push เข้า `main`
- รายชื่อสินค้าหลัก = `data/stock_2026-09-28.csv` (105 รหัสจริง) · ตารางตั้ง `on update cascade` ให้แก้รหัสทีหลังได้โดยประวัติไม่พัง
- รูปเก็บใน bucket `shelf-photos` แบบ private · ข้อความตอบยาวไม่เกิน 5,000 ตัวอักษร (ข้อจำกัดของ LINE)

## 5 จุดที่คนใช้จริงจะเจอ แต่ spec ไม่ได้พูดถึง (มีเทสต์คุมไว้แล้ว)
1. **พิมพ์เลขไทย** `๗ ๘` → ต้องอ่านเป็น 7 กับ 8 (งาน 3)
2. **นับหลังเที่ยงคืน** เซิร์ฟเวอร์ใช้เวลา UTC แต่นับตอนตี 1:30 วันที่ 29 ต้องเข้ารอบวันที่ 29 (งาน 5)
3. **CSV ที่เปิดแก้ใน Excel แล้วเซฟ** Excel แอบใส่ BOM ไว้หน้าไฟล์ → ต้องยังอ่านได้ (งาน 2)
4. **LINE ตอบกลับไม่สำเร็จ** (reply token หมดอายุ / LINE ส่งซ้ำ) → webhook ต้องยังตอบ 200 และยอดต้องบันทึกไปแล้ว (งาน 6)
5. **แก้รหัสสินค้า** หลังมียอดนับแล้ว → ยอดเก่าต้องตามไปด้วย ไม่พัง (งาน 8)

## งาน 1 — โครงโปรเจกต์ + โหลด config
- **ทำอะไร:** สร้าง `pyproject.toml`, `.gitignore`, `.env.example`, `config.yaml` ตัวอย่าง 2 ชั้น, GitHub Action รันเทสต์, และ `config.py` ที่อ่าน + ตรวจ `config.yaml`
- **ตรวจอะไรบ้าง:** รหัสชั้นต้องเป็น A-Z/0-9/- (ตัวเล็กแปลงเป็นตัวใหญ่ให้) · ทุกชั้นต้องมีสินค้า · สินค้า 1 ตัวอยู่ได้ชั้นเดียว · ต้องมี `line_basic_id` · allowlist ว่าง = ใครก็นับได้
- **เสร็จเมื่อ:** เทสต์ 10 ข้อผ่าน

## งาน 2 — ใบนับเป็น CSV + ตัวอ่าน + ตัวเตรียมข้อมูลลง DB — ✅ เสร็จ 2026-09-29
- **ทำอะไร:** `data/stock_2026-09-28.csv` 105 รายการ ถอดจากใบนับ **28/9** ที่เห็นรหัสครบ → **ไม่มีรหัส TEMP แล้ว** · `stock_csv.py` อ่าน CSV · `seed.py` แปลง config + CSV เป็นแถวที่จะใส่ DB
- **ตรวจอะไรบ้าง:** รหัสซ้ำ · จำนวนที่ไม่ใช่จำนวนเต็ม · คอลัมน์หาย · BOM จาก Excel · ยอดติดลบในระบบเก็บตามจริง (PANDORA II หน้าร้าน -9) · **คงเหลือต้อง = หลังร้าน + หน้าร้าน ทุกแถว** (ทั้ง 105 แถวผ่าน = ถอดตัวเลขถูก) · สินค้าใน config ที่ไม่มีใน CSV ถูกปฏิเสธ
- **ผล:** เทสต์ 11 ข้อผ่าน
- **ณัฑฒ์ต้องทำ:** ดูชื่อ 2 ตัวที่ `needs_review=true` (HB0083, NA0031)

## งาน 3 — อ่านข้อความแชท
- **ทำอะไร:** `parser.py` แปลงข้อความเป็นคำสั่ง: `ชั้น A2` → เปิดชั้น · `7 8` / `7,8` / ขึ้นบรรทัดใหม่ / เลขไทย → ยอด · `ข้าม` / `สรุป` / `ปิดรอบ` · ติดลบ → แจ้งเตือน · อย่างอื่น → ไม่รู้จัก
- **เสร็จเมื่อ:** เทสต์ 15 ข้อผ่าน

## งาน 4 — ที่เก็บข้อมูลจำลอง
- **ทำอะไร:** `repo.py` กำหนดว่าฐานข้อมูลต้องทำอะไรได้บ้าง (เปิด/ปิดรอบ, ดึงชื่อ/ยอดในระบบ, บันทึก/ดูยอด, จำชั้นที่เปิด, เก็บรูป) + `InMemoryRepo` ที่เก็บในหน่วยความจำไว้เทสต์
- **เสร็จเมื่อ:** เทสต์ 6 ข้อผ่าน (รอบละวัน, ปิดรอบ, นับซ้ำทับ, ฯลฯ)

## งาน 5 — กติกาของ bot + ข้อความภาษาไทย
- **ทำอะไร:** `messages.py` (ข้อความตอบทั้งหมด) + `service.py` (`StockService`) ที่รวมกติกาทุกข้อ: เปิดชั้น → แสดงรายการ + ยอดระบบ · รับยอด → บันทึก → บอกเฉพาะรายการที่ไม่ตรง → ขอรูป · รับรูป → ผูกกับชั้นที่เปิดอยู่ · สรุป / ปิดรอบ · คนนอก allowlist → ไม่ตอบ · ฐานข้อมูลล่ม → "บันทึกไม่สำเร็จ"
- **เสร็จเมื่อ:** เทสต์ 19 ข้อผ่าน · รวมทั้งโปรเจกต์ 60 ข้อ

## งาน 6 — Webhook ของ LINE
- **ทำอะไร:** `app.py` รับข้อความจาก LINE → ตรวจลายเซ็น (ผิด = 400) → ส่งข้อความ/รูปให้ `StockService` → ตอบกลับ · รับเฉพาะแชท 1:1 (ไม่รับในกลุ่ม) · ตอบกลับพังก็ยังตอบ LINE ว่า 200 · ข้อความยาวเกินตัดที่ 5,000 · มี `/health` ไว้เช็กว่าเซิร์ฟเวอร์ยังอยู่
- **เสร็จเมื่อ:** เทสต์ 9 ข้อผ่าน

## งาน 7 — ป้าย QR + สคริปต์
- **ทำอะไร:** `qr.py` สร้างลิงก์ LINE ที่เติมข้อความ `ชั้น A2` ไว้ให้ + รูปป้าย QR ที่มีรหัสชั้นตัวใหญ่ด้านล่าง · `make_qr.py` สร้าง PNG ทุกชั้นใน `out/qr/` (ไม่ยอมทำถ้ายังไม่ได้ใส่ Basic ID จริง) · `import_csv.py` ใส่ CSV + ผังชั้นลง Supabase
- **เสร็จเมื่อ:** เทสต์ 3 ข้อผ่าน + เปิดดูรูปป้ายด้วยตาแล้ว QR กับรหัสชั้นชัด

## งาน 8 — Supabase: ตาราง, ตัวเชื่อม, Action
- **ทำอะไร:** `npx supabase init` · ไฟล์ migration สร้าง 8 ตาราง + bucket รูป (เปิด RLS ไม่มี policy = เข้าได้เฉพาะเซิร์ฟเวอร์ที่ถือ service key) · `SupabaseRepo` · สคริปต์ `smoke_supabase.py` ทดสอบกับ Supabase จริงโดยใช้วันที่ปี 2000 แล้วลบทิ้ง · Action `db-migrate`
- **เสร็จเมื่อ:** เทสต์เดิมผ่านทั้งหมด (72 ข้อ) · smoke script จะรันได้หลังณัฑฒ์สร้างโปรเจกต์ Supabase (งาน 9)
