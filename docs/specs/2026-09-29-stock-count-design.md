# 📦 Spec — ระบบนับสต็อกหลังร้าน (POC · สาขา MBK)

← [[Project - Stock Count]] · [[Code Hub - Avatar]] · 🇬🇧 English: [[2026-09-29-stock-count-design-en]] · 🕘 ฉบับก่อน: [[2026-09-28-stock-count-design]] · 🆕 ฉบับล่าสุด: [[2026-09-30-stock-count-design]]

## TL;DR
ณัฑฒ์ (คนนับใน pilot) กด **เริ่มนับ** → เดินไปแต่ละชั้นหลังร้าน สแกน QR ที่ชั้น → **หน้า UI ใน LINE เด้งขึ้นมา** บอกว่าชั้นนี้มีสินค้าอะไร ยอดที่ควรมี (expected) และยอดที่นับได้ครั้งก่อน → กรอกยอดจริง + ถ่ายรูปชั้น → **โมเดล CV ตัวเล็ก (Roboflow YOLO) นับจากรูปเพื่อจับความผิดพลาดของคน** → จบกะกด **ส่งยอด** → ยอดเข้า Supabase + สรุปรายการที่ไม่ตรงกับระบบ + เวลาที่ใช้ → รายอาทิตย์ดูว่าสินค้าไหนขายดี
มี **minimap** (แผนผังห้องหลังร้าน แบบแผนผังร้านค้าใน Siam Paragon) เป็นสารบัญ SKU — ค้นหาสินค้าแล้วรู้ว่าอยู่ชั้นไหน ฝั่งซ้ายหรือขวา · ออกแบบให้เพิ่มชั้น/สาขาได้ภายหลัง

- **Pilot:** สาขามาบุญครอง (MBK) หลังร้าน · 1 เดือน · คนนับ = ณัฑฒ์
- **เฟส 1 (spec นี้):** หน้า UI + minimap + time clock + เก็บยอดและรูป + CV ตัวเล็กตรวจยอด
- **เฟส 2:** YOLO นับแยกทีละ SKU · **เฟส 3:** โมเดลเทรนตัวเองจากรูปที่ส่งเข้ามา (เขียน spec แยก)

## เป้าหมาย / วัดผล (ตลอด pilot 1 เดือน)
- เป้าหมายใหญ่: digital transformation ของการนับสต็อก → เอาผล pilot ไปเสนอบริษัท
- ✅ เวลานับหลังร้านต่อรอบ **< 10 นาที** (time clock วัดทุกรอบ · จับเวลาแบบกระดาษ 1 รอบก่อนเริ่มเป็น baseline)
- ✅ ทุกวันที่นับ มีรอบนับครบทุกชั้นใน Supabase
- ✅ จบกะแล้วเห็นรายการที่ไม่ตรงกับระบบทันที
- ✅ นับได้ว่า CV จับความผิดพลาดของคนได้กี่ครั้ง (ธง ⚠️ ที่นับซ้ำแล้วคนนับผิดจริง)
- ✅ มีรายงานสินค้าขายดีรายอาทิตย์
- ✅ มีรูปชั้นพร้อมยอดที่ยืนยันแล้ว สะสมเป็น dataset ให้เฟส 2–3

## สถาปัตยกรรม
```
[QR ที่ชั้น L1] ──กล้อง LINE──> https://liff.line.me/<LIFF_ID>?shelf=L1
                                        │ (เปิดในแอป LINE)
                                        ▼
                     [FastAPI (Python) — สร้างหน้า HTML เอง]
                       /map        minimap + ปุ่ม เริ่มนับ / ส่งยอดจบกะ
                       /shelf/L1   รายการสินค้า + expected + ครั้งก่อน + ช่องกรอก + ถ่ายรูป
                       /report     สรุปขายดีรายอาทิตย์
                         │                     │                      │
                  ตรวจตัวตนผ่าน LINE     Roboflow API          Supabase
                  (LIFF ID token)       (นับจากรูป)      (Postgres + Storage)
                                                                 │
                                          LINE Messaging API ── push สรุปจบกะเข้าแชทณัฑฒ์
```
- **Python 3.11+** · `fastapi` + `jinja2` (หน้า HTML) · `httpx` (เรียก LINE verify / Roboflow) · `supabase` · `line-bot-sdk` v3 (push สรุป) · `pyyaml` · `qrcode[pil]` · `pytest`
- JavaScript มีแค่ตัวเชื่อม LIFF สั้น ๆ (เอา ID token ของผู้ใช้) — ที่เหลือเป็น HTML/CSS ธรรมดา ไม่ใช้ framework (minimap ก็เป็น CSS grid เรียบ ๆ ดูแลง่ายระยะยาว)
- **UTF-8 ทุกที่:** ไฟล์โค้ด/เทมเพลต/CSV เป็น UTF-8 · ทุกหน้ามี `<meta charset="utf-8">` · response เป็น `text/html; charset=utf-8` · CSV อ่านแบบ `utf-8-sig` (รับไฟล์ที่ Excel เซฟ)
- config คนแก้ = `config.yaml` · ความลับ = `.env` (`LINE_CHANNEL_ACCESS_TOKEN`, `LINE_LIFF_CHANNEL_ID`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `ROBOFLOW_API_KEY`) ไม่ขึ้น GitHub
- **ไม่มี webhook แชทแล้ว** — ข้อมูลทั้งหมดส่งผ่านหน้า UI · LINE OA ใช้แค่เป็นทางเข้า (rich menu → minimap) และรับข้อความสรุปจบกะ

## การใช้งาน (1 รอบ)
1. เปิด LINE OA → rich menu **"แผนผังหลังร้าน"** → หน้า **minimap**: ชั้นซ้าย `L1…` / ชั้นขวา `R1…` เรียงตามจริง · สีเทา = ยังไม่นับ · เขียว = นับแล้ว · ส้ม = มีธง ⚠️ · ช่องค้นหา SKU/ชื่อ → ไฮไลต์ชั้นที่มีสินค้านั้น
2. กด **⏱️ เริ่มนับ** → เริ่มจับเวลารอบวันนี้ (ถ้าลืมกด ระบบเริ่มให้เองตอนเปิดชั้นแรก)
3. สแกน QR ที่ชั้น (หรือแตะชั้นบน minimap) → หน้า **ชั้น L1**:

   | สินค้า | ระบบ (expected) | ครั้งก่อน | นับได้ |
   |---|---|---|---|
   | อุระกาวาท | 10 | 10 (28/9) | [ ช่องกรอก ] |
   | กัณฑรา | 5 | 5 (28/9) | [ ช่องกรอก ] |

   + ปุ่ม **📷 ถ่ายรูปชั้น** + ปุ่ม **บันทึกชั้นนี้**
4. บันทึก → ยอดเก็บเป็นของรอบวันนี้ (แก้ซ้ำได้จนกว่าจะส่งยอด) → ถ้ามีรูป: ส่งไป Roboflow → เทียบ **ผลรวมตามประเภทบรรจุภัณฑ์** เช่น "ขวด: CV นับ 14 / คนกรอก 15" → ต่างเกินเกณฑ์ = ธง ⚠️ "ลองนับชั้นนี้อีกรอบ" · ไม่ต่าง = ✅
5. กลับ minimap → ชั้นถัดไป
6. กด **📤 ส่งยอดจบกะ** → หยุดจับเวลา → ปิดรอบ → หน้าสรุป: เวลาที่ใช้ · ชั้นที่ยังไม่นับ · สินค้าที่ไม่ตรงกับระบบ · ธง CV → push สรุปเดียวกันเข้าแชท LINE ของณัฑฒ์
7. หน้า **/report** → สินค้าขายดีรายอาทิตย์

**แสดงยอดในระบบให้คนนับเห็น** (ไม่ใช้ blind count) — เพื่อความโปร่งใส ตรงกับวิสัยทัศน์ของ CEO · และนับได้เร็วกว่า · ดูเหตุผลเทียบใน [[R&D - Stock Count คู่แข่ง]]

## CV ตรวจยอด (โมเดลตัวเล็ก)
- **โมเดล:** Roboflow โปรเจกต์ object detection คลาส `bottle`, `pouch`, `bag`, `box`, `book` · เริ่มจาก 50–100 รูปชั้นหลังร้านที่ติด label เอง · เทรนบน Roboflow (ขนาดเล็กสุด) · เรียกผ่าน Roboflow hosted API (ไม่ต้องมี GPU)
- **ข้อมูลเสริม:** ทุก SKU มี `packaging` (หนึ่งใน 5 คลาสข้างบน) ในรายชื่อสินค้า
- **การเทียบ:** ต่อชั้น ต่อคลาส → `human = ผลรวมยอดที่กรอกของ SKU ที่เป็นคลาสนั้น` · `cv = จำนวนกล่องที่โมเดลเจอ (confidence ≥ เกณฑ์)` · ธง ⚠️ เมื่อ `|cv − human| > max(1, 10% ของ human)` (ตั้งค่าได้ใน `config.yaml`)
- **ถ้ายังไม่มีโมเดล / API ล่ม / ไม่ถ่ายรูป** → บันทึกยอดตามปกติ สถานะ CV = "ไม่ได้ตรวจ" (CV เป็นตัวช่วย ไม่ใช่ด่านบังคับ)
- ⚠️ ของที่ซ้อนกันมาก (หนังสือเป็นตั้ง, ซองในตะกร้า) CV น่าจะนับขาด → ช่วง pilot ดูสถิติแล้วปิด CV รายชั้นได้ใน `config.yaml`

## ข้อมูล (Supabase)
| ตาราง | คอลัมน์หลัก | หมายเหตุ |
|---|---|---|
| `products` | `sku` PK, `name`, `category`, `packaging` | จาก CSV |
| `shelves` | `code` PK (`L1`, `R2`…), `label`, `side` (`L`/`R`), `position`, `cv_enabled` | จาก config.yaml |
| `shelf_products` | `shelf_code`, `sku`, `position` | ลำดับที่แสดง |
| `stock_snapshots` | `sku`, `back_qty`, `as_of` | ยอดในระบบ (expected) · import ได้หลายวัน |
| `count_sessions` | `id`, `count_date` unique, `started_at`, `ended_at`, `line_user_id` | 1 รอบ/วัน · **time clock** = `ended_at − started_at` |
| `counts` | `session_id`, `shelf_code`, `sku`, `expected_qty`, `counted_qty`, `updated_at` | unique (session, sku) · นับซ้ำ = ทับ |
| `shelf_photos` | `session_id`, `shelf_code`, `storage_path`, `cv_counts` (jsonb), `human_counts` (jsonb), `cv_status` (`ok`/`flagged`/`skipped`) | รูปใน bucket `shelf-photos` = dataset เฟส 2–3 |

- `expected_qty` คัดลอกจาก snapshot ตอนนับ → รายงานย้อนหลังไม่เพี้ยน
- "ครั้งก่อน" = `counted_qty` ล่าสุดของ SKU นั้นจากรอบก่อนหน้า
- เก็บแค่ LINE user ID ไม่เก็บชื่อ/เบอร์ · FK ที่ชี้ `products.sku` ใช้ `on update cascade` (แก้รหัสได้ ประวัติไม่พัง)
- **Supabase ↔ GitHub:** GitHub Action รัน `supabase db push` เมื่อ push เข้า `main` (free plan)
- schema ที่ขึ้นไปแล้ว (8 ตาราง) แก้ด้วย **migration ใหม่** ไม่แก้ไฟล์เดิม: เพิ่ม `packaging`, `side/position/cv_enabled`, `started_at/ended_at`, คอลัมน์ CV · ลบ `user_state` (หน้า UI รู้ชั้นจาก URL แล้ว)

## รายงานขายดีรายอาทิตย์
- ยอดที่หายไปของแต่ละ SKU = ผลรวมของ `max(0, นับครั้งก่อน − นับครั้งนี้)` ระหว่างรอบนับในอาทิตย์นั้น
- ยอดที่ **เพิ่ม** ถือว่าเป็นของเข้า (restock) ไม่นับเป็นยอดขาย
- ⚠️ เป็น **ค่าประมาณ** เพราะหลังร้านมีการย้ายของไปหน้าร้านด้วย ไม่ใช่ขายออกทั้งหมด → ใช้ดูแนวโน้ม "ของไหนไหลออกเร็ว" ไม่ใช่ตัวเลขบัญชี
- หน้า `/report?week=2026-W40` แสดง 10 อันดับ + กราฟแท่งง่าย ๆ

## config.yaml (ตัวอย่าง)
```yaml
branch: mbk
line_basic_id: "@CHANGE-ME"      # Basic ID ของ LINE OA
liff_id: "CHANGE-ME"             # LIFF app ID (ใช้สร้างลิงก์ใน QR)
allowed_line_user_ids: []        # pilot: ใส่ LINE user ID ของณัฑฒ์
cv:
  model: "stock-count-packaging/1"   # Roboflow project/version
  min_confidence: 0.5
  tolerance_ratio: 0.10               # ธงเมื่อต่างเกิน max(1, 10%)
shelves:
  L1: { label: "ชั้นเหล็กซ้าย แถว 1", skus: [HB0001, HB0003, HB0004] }
  L2: { label: "ชั้นเหล็กซ้าย แถว 2", skus: [NA0025, NA0026] }
  R1: { label: "ตู้ขาวขวา ช่อง 1", skus: [NA0031, NA0032], cv_enabled: false }
```
- ฝั่ง (`L`/`R`) อ่านจากตัวอักษรแรกของรหัสชั้น · ลำดับบน minimap = ลำดับในไฟล์
- ผังจริงรอณัฑฒ์เดินจด

## Error handling
| เหตุการณ์ | ระบบทำอะไร |
|---|---|
| เปิดหน้านอกแอป LINE / token ไม่ผ่าน | หน้า "เปิดผ่าน LINE เท่านั้น" · HTTP 401 |
| ผู้ใช้ไม่อยู่ใน allowlist | หน้า "ไม่มีสิทธิ์" · HTTP 403 · log |
| ชั้นที่ไม่มีใน config | หน้า "ไม่พบชั้น X" + ลิงก์กลับ minimap · HTTP 404 |
| ช่องกรอกว่าง / ไม่ใช่ตัวเลข / ติดลบ | ฟอร์มขึ้นเตือนที่ช่องนั้น ไม่บันทึกอะไรเลย (ทั้งชั้นหรือไม่เลย) · รับเลขไทย ๐–๙ ด้วย |
| รอบวันนี้ส่งยอดไปแล้ว | หน้าชั้นเป็นแบบอ่านอย่างเดียว + บอกว่าส่งแล้ว |
| Roboflow ล่ม / ช้าเกิน 10 วินาที | บันทึกยอดปกติ · CV = "ไม่ได้ตรวจ" · log |
| Supabase ล่ม | "บันทึกไม่สำเร็จ ลองอีกครั้ง" · ค่าที่กรอกยังอยู่ในฟอร์ม · log |
| push สรุปเข้า LINE ไม่สำเร็จ | รอบยังปิดตามปกติ · หน้าสรุปยังดูได้ · log |
